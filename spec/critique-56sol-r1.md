1. **blocker — The plan is not remotely buildable in ~2 days.** Ten migration layers, duplicate TypeScript/Postgres domain engines, IndexedDB transactions, cross-tab synchronization, generic importer/diffing, versioned scoring editors, dependency graphs, idempotency receipts, audit UI, conflict projections, account invitations, full CRUD, four test suites, and nine public routes is a multi-week build. **Fix:** freeze a 48-hour MVP: official seed; public home/sport/schedule/tally; coordinator scoring; admin fixture/roster/award/account essentials; three fixed generic scoring renderers; one atomic scoring RPC; one fixture/conflict RPC; Realtime invalidation plus 5-second polling. Cut importer UI, re-import merging, audit UI, operations dashboard, team pages, sharing image, mock cross-tab synchronization, generic profile builder, dependency-graph UI, exports, and full mock/SQL parity.

2. **blocker — Section 11 is truncated mid-rule, so the binding user-added scope is not specified.** It stops at “MVP checks use current active memberships” and omits the actual overlap algorithm, save workflow, warning/acknowledgement behavior, conflict query, coordinator override rules, conflict-view semantics, RLS disclosure, and tests. **Fix:** complete §11 before implementation with exact interval derivation, fixture eligibility, self-exclusion, participant resolution, player/venue conflict result shape, transactional report-hash acknowledgement, coordinator/admin override rules, and conflict-list queries.

3. **blocker — Coordinator scheduling permissions contradict each other.** §2 calls coordinators “scoring only”; the policy matrix forbids arbitrary scheduling edits and all `match_slots` edits, while §5 and §11 say coordinators create/edit own-sport fixtures, including teams. A fixture cannot be created without slots. **Fix:** replace all earlier language with one final rule: coordinators may call `create_fixture`/`update_fixture` for their sport; the RPC atomically creates/updates the match and fixed-entry slots, applies the division’s profile, runs conflicts, and records acknowledgement. Restrict group-rank/match-outcome dependency slots and bracket topology edits to admins.

4. **blocker — The Supabase GitHub integration is not the deployment path described.** The addendum makes GitHub-delivered migrations binding, but the checklist tells a non-expert to link production and run `supabase db push`, creating two competing production migration paths and drift risk. **Fix:** designate merge-to-`main` through the Supabase GitHub integration as the sole normal production migration path. Reserve CLI reset/push for local development or documented emergency recovery; document integration logs, migration-history verification, rollback-by-forward-migration, and branch/preview behavior.

5. **blocker — `supabase/seed.sql` will not automatically seed production through normal migration deployment.** The draft calls it development-only, while launch depends on official teams, volleyball structure, fixtures, and profiles being present. The setup’s vague “event-seed command” is neither specified nor guaranteed to exist. **Fix:** define one explicit production bootstrap path: either an idempotent reviewed official-data migration or a concrete authenticated CLI/script invoking an admin seed RPC. State that `seed.sql` is used by local reset/preview only, provide the exact command for production, checksum the official dataset, and add a post-seed count verification.

6. **major — Public RLS exposes private columns because RLS filters rows, not columns.** Anonymous SELECT on `match_slots`, `division_results`, groups, profiles, and importable entities can expose override reasons, confirmer UUIDs, tie-resolution reasons, provenance, hashes, and internal review state despite claims that these remain private. **Fix:** revoke anonymous access to base tables containing mixed-sensitivity columns. Expose typed public RPCs or dedicated public projection views/tables containing only approved fields. Publish only the sanitized `event_updates` projection.

7. **major — The SECURITY DEFINER/RLS design is too vague to be safely implementable.** A `NOLOGIN NOBYPASSRLS` function owner executes as that owner, not as `authenticated`; policies scoped only `TO authenticated` will not apply. Merely calling `auth.uid()` does not fix role applicability. **Fix:** provide exact mechanics: owner and grants for each command function, policies explicitly applicable to the command-owner role, caller checks based on `auth.uid()`, pinned `search_path`, revoked `PUBLIC` execution, and integration tests proving cross-sport writes fail. Alternatively, perform user-scoped direct DML under ordinary RLS and reserve SECURITY DEFINER only for the few atomic workflows that need it.

8. **major — The policy matrix is not a per-table RLS specification.** Phrases such as “published parent chain” and “internal command increment” do not define actual `USING`/`WITH CHECK` predicates, INSERT versus UPDATE permissions, or how coordinator fixture creation changes ancestry safely. **Fix:** add a concise policy table per operation with named helper predicates such as `is_admin()`, `coordinates_sport(uuid)`, `can_read_match(uuid)`, and `can_write_match(uuid)`, then show which roles receive SELECT/INSERT/UPDATE/DELETE/EXECUTE on every table and RPC.

9. **blocker — The design does not demonstrate the binding <1-second viewer update target.** Realtime emits an invalidation, waits 50–100 ms, and then performs another snapshot request; the event-wide lock and synchronous advancement/conflict/award recomputation add further latency. No acceptance metric measures commit-to-render time. **Fix:** include the public-safe score summary in `event_updates` and apply it immediately, then refresh derived standings in the background. Add an acceptance test such as p95 commit-to-visible-score under one second across two browsers on hosted Supabase; retain 5-second polling as fallback.

10. **major — The event-wide revision lock serializes every score and fixture save across all sports.** During concurrent matches, unrelated score updates queue behind standings, advancement, conflict, award, audit, and outbox work, directly endangering the latency requirement. **Fix:** lock the affected match and dependency chain only; use a sequence/identity value
